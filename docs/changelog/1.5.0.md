# 1.5.0

_Released 2026-11-27_

Bug sweep (plan `101-bug-sweep`, #86 #87 #88): eight adversarial reviewers, fixes test-first, proven on real tmux 2.6 to 3.8 and in real VSCodium.

**Persistent terminals**

- fix: full-screen TUIs such as Claude Code render correctly. A client whose locale is not UTF-8 no longer turns every non-ASCII glyph into `_` (tmux `-u`). 24-bit colour, synchronized output and (tmux 3.4+) hyperlinks are declared for our own client only on tmux 3.2+, with no server state written; older tmux gets a guarded `xterm*:Tc` override that respects any `Tc` setting of yours. `COLORTERM=truecolor` is set in new panes on 3.2+
- fix: a session is no longer reaped while a detached task is printing output: age is measured on the remote's clock (a client clock days ahead used to reap live sessions) and on the newest activity of every window, read in one tmux snapshot
- fix: no second client on a session after closing and reopening the window. VS Code sometimes revives terminals through its pty host without their launch arguments; they were not recognised, so after 10 s a second client was attached to each session and a session you had exited in between came back. Such terminals are now recognised by process id when VS Code reports it within 2 s (a later report is not yet picked up; found by the real-VSCodium acceptance run; present in 1.4.2)
- fix: a revived tab is never handed a session that is already on screen; a session you just closed is never reopened by a reconcile that races its kill; a queued reclaim never takes a session over from another machine that picked it up meanwhile
- fix: wiring races: a superseded connect no longer turns every New Terminal into a plain shell; a `remote.SSH.tmux.*` change made during the first connect is applied, not dropped; turning persistent terminals off takes effect at once and leaves no default-profile value behind; the "tmux required" error shows once per window per host
- fix: the PageUp/PageDown scroll binding applies only to our own sessions (your own tmux sessions, and `ssh` inside ours, get the keys untouched) and never replaces a binding of yours
- fix: a short noise line no longer breaks the session list; the close watch retries after a failed start
- docs: persistent terminals do not get VS Code's terminal environment (remote `code` CLI, `GIT_ASKPASS`, extension variables), and why

**Connection and security**

- fix: known_hosts host fields are OpenSSH pattern lists (`*`, `?`, `!` negation, case-insensitive). `@revoked * <key>` was ignored and a revoked key accepted; a wildcard or differently-cased record downgraded a changed key to a first-connect prompt
- fix: host-key algorithms prefer the key types already on file, so a host recorded with only `ssh-rsa` or ecdsa no longer fails as a possible MITM
- fix: `%h`/`%n`/`%r`/`%p` values that a ProxyCommand actually uses are vetted, more strictly than OpenSSH: a value containing `$`, `\`, whitespace, quotes, `;&|<>(){}`, backticks or glob/history characters, or starting with `-`, is refused, and a token in the program name is refused. An accepted value is still an ordinary word, so never put `%h`/`%r` in a command position of a shell-backed ProxyCommand (`sh -c "%h"`). **A login such as `CORP\me` or `John Smith` is refused when the ProxyCommand uses `%r`**
- fix: a newline in `remote.SSH.serverDownloadUrlTemplate` could run shell on the remote through a comment in the install script; line breaks are refused, and the template is never logged (it can carry a mirror credential)
- fix: **`user@host:port` beats the SSH config's `User`/`Port`**, as in `ssh`; a ProxyJump hop's user is its own `user@`, then its config `User`, then the local user
- fix: the first of ProxyJump/ProxyCommand wins and `none` cancels both; single quotes group in ProxyCommand; ProxyJump hops expand `HostName %h`
- fix: **`Include` pathnames are separated by whitespace only, as in OpenSSH** (`Include a.conf,b.conf` now names one file; write `Include a.conf b.conf`)
- fix: encrypted legacy-PEM and PPK keys prompt for their passphrase; a failed tunnel channel closes its socket instead of hanging the reconnect; ports outside 1-65535 are refused; PowerShell quoting doubles the Unicode quote look-alikes

**Clipboard image paste**

- fix: an image over 20 MB reports "too large"; the extension stops waiting for the upload after 60 s (the transfer itself is not cancelled); the Windows readers fail cleanly and quote paths with smart apostrophes; a remote home with control characters is refused

**Tooling and maintenance**

- build: toolchain on Node 24 LTS (Node 20 is end-of-life; the extension still runs on VS Code's Electron Node 20, `engines.vscode ^1.90.0` unchanged); every dependency at its latest mature release; ssh-config 5.3, `@types/ssh2` 1.x
- ci: superseded PR runs cancelled, every job has a timeout, npm cache on PR/main CI (never on release workflows), Markdown-only changes run CI, the changelog extraction matches the exact version
- fix(dx): `bin/check` stops on the first failing step (a compile or lint failure could exit 0); `bin/` scripts fail fast without `node_modules`; git hooks never download tools
- chore(dz): weekly Monday maintenance: a read-only `health` brief (red main, flaky jobs, Dependabot, upstream drift, advisories, release judgement) and a `maintain` brief that lands the week's upkeep in one PR; stale issues and PRs are handled by the maintainer policy alone (60 days)
